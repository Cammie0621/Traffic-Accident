# 六都傷亡交通事故時空地圖

資料視覺化期末專題｜使用 Streamlit 探索六都傷亡道路交通事故的時間、空間、肇因與當事者分布。

> 專案狀態：規劃與開發中。本文件描述預定功能與建議目錄，實際功能、執行指令及部署網址將依實作更新。

## 專題介紹

本專題使用政府資料開放平臺的 A1／A2 傷亡道路交通事故資料，聚焦臺北市、新北市、桃園市、臺中市、臺南市與高雄市。透過互動篩選與多種圖表，建立「整體 → 何時 → 哪裡 → 肇因與當事者 → 檢視假設」的探索流程。

### 核心問題

- 事故件數隨月份如何變化？不同年度有何差異？
- 事故集中在哪些星期與時段？
- 六都的事故位置如何分布？
- 常見的警方研判主要肇因有哪些？
- 不同車種類別的事故當事者年齡分布有何差異？

## 圖表規劃

新增六都比較長條圖：X＝事故件數、Y＝城市，用於總覽的城市比較，由 B 負責；肇因長條圖仍由 F 負責。長條圖重複使用不另算圖表種類。

| 圖表 | 軸與編碼 | 統計單位 | 用途 |
| --- | --- | --- | --- |
| 折線圖（課堂） | X：月份；Y：事故件數；顏色：年度 | 事故件數 | 比較月別變化 |
| 熱力圖（延伸） | X：小時；Y：星期；顏色：事故件數 | 事故件數 | 呈現兩個時間維度的集中程度 |
| 水平長條圖（課堂） | X：事故件數；Y：主要肇因 | 事故件數 | 比較主要肇因，提供車種篩選 |
| 地圖（課堂） | 位置：經緯度；顏色：A1／A2；點位大小：傷亡人數 | 每案一個位置 | 探索事故分布；聚合模式另標示件數圖例 |

共包含至少四種課堂圖表，以及熱力圖、箱型圖兩種延伸圖表。

## 資料整理與統計口徑

### 兩個資料層級

- **事故表 `accidents`**：一案一列，用於事故數、傷亡數、地圖、時間與主要肇因分析。
- **當事者表 `participants`**：一位當事者一列，用於年齡、車種等分析；以 `accident_id` 連接事故表。

### 預定處理流程

1. 統一跨年度欄位、資料型別及分類名稱，只讀取必要欄位。
2. 轉換民國／西元日期，解析時間並產生月份、星期與小時。
3. 優先查找可靠事故識別欄位；若無，建立候選複合鍵並檢查誤合併與缺漏。「當事者順位＝1」需驗證後才能用於建立事故表，不直接視為可靠案件編號。
4. 建立警局名稱與縣市對照，並用發生地點或座標交叉檢查；國道等特殊管轄案件另外處理，無法確認者標示未判定。
5. 解析死亡受傷人數；若同案各列重複記載全案傷亡，僅在事故表計算一次。
6. 座標缺失或無效者不繪製地圖，但保留於適用的非地圖統計，呈現總件數與可定位件數差異。
7. 檢查年齡空值、0 與異常值的原始定義後制定規則；不把 0 自動當成缺值。年齡無效者僅排除於年齡分析。
8. 檢查重複紀錄，不以事故欄位相同就刪除不同當事者。
9. 地點文字正規化後才彙整排名；明確區分路口、路段與地址，避免誤稱為同一事故點。
10. 輸出清理資料與清理紀錄，保留前後筆數、排除原因及資料涵蓋期間。

### 車種篩選

「涉及機車的事故」定義為任一當事者屬於選定機車類別的事故；先由當事者表找出案件，再對事故 ID 去重計數。多選車種採聯集，不重複加總。同案可涉及多種車種，因此不同車種各自的事故數不一定可相加。

若採第一當事者車種分組，須另行標示；第一當事者不等於唯一肇事者或法律責任人。

以下假設已完成上述目錄、依賴清單及前處理腳本，且 Python 已安裝。

```bash
python -m venv .venv
```

啟用虛擬環境：

```powershell
# Windows PowerShell
.venv\Scripts\Activate.ps1
```

```bash
# macOS / Linux
source .venv/bin/activate
```

安裝依賴、依資料來源下載 CSV 至 `data/raw/`，再執行：

```bash
python -m pip install -r requirements.txt
python scripts/preprocess.py
python -m streamlit run app.py
```

### 頁面組裝與程式介面

**一個人負責的模組不等於一個獨立頁面。** 多人共用的頁面檔由 B 管理，各人修改自己的模組，減少合併衝突。

| 網站頁面 | 引用模組／成果 | 維護分工 |
| --- | --- | --- |
| 總覽 | B 城市比較＋C 指標卡、月別趨勢 | B 組裝，B、C 各維護自己的模組 |
| 時間規律 | D 時間分析模組 | B 建頁面入口，D 維護內容 |
| 空間熱點 | E 地圖與表格模組 | B 建頁面入口，E 維護內容 |
| 肇因與當事者 | A 直方圖＋F 肇因與箱型圖 | B 組裝，A、F 各維護自己的模組 |
| 方法與結論 | A 提供方法，全員提供觀察 | B 彙整，全員核對 |

建議每個模組提供一個畫面函式；以下是待 A、B 確認的介面規格，並非已完成程式：

```python
def render(accidents, participants, *, key_prefix):
    """接收已套用全站篩選的兩張表，完成局部控制、彙整及畫面。"""
    ...
```

- B 在頁面先取得共用篩選後的事故表，再以事故 ID 取出對應當事者，傳給模組。
- 各模組不自行重新讀取原始 CSV，不改寫傳入資料；新增欄位時使用副本。
- widget key 使用自己的前綴，例如 `age_bin_width`、`city_sort`，避免同頁重名。
- 同頁 A、F 的共用車種控制由頁面建立一次，再把相同車種條件傳入兩個模組；實際函式參數記錄於開發說明。
- 模組函式供網站 import 呼叫，不以 `streamlit run components/xxx.py` 作為正式啟動方式。
- 共用欄位、資料型別、有效值與函式變更均記錄到 `docs/data_dictionary.md` 和 `docs/development.md`。

## Demo 流程

1. 總覽：設定年度與城市，觀察事故件數及月份變化。
2. 時間：比較星期、小時與平日／週末分布。
3. 空間：選取時段，觀察事故地圖及熱點表格。
4. 當事者：切換車種，查看主要肇因與年齡分布。
5. 結論：對照原先假設，說明證據與限制。

## 驗證清單

- [ ] 相同篩選條件下，各頁事故件數一致。
- [ ] 傷亡人數沒有因當事者列數而重複加總。

- [ ] 缺資料月份與真正零件數已區分。
- [ ] 車種多選不重複計算同一事故。
- [ ] 地圖說明可定位與無法定位的件數。
- [ ] 年齡分析顯示有效樣本數與排除規則。
- [ ] 無資料、重設篩選與大型資料載入可正常處理。

## 分析限制

- 本專題聚焦 A1／A2 傷亡事故，不代表所有道路事故。
- 事故數或密集程度不等於個人事故風險；缺少車流量、行駛里程等曝險分母，不能據此判定某城市、時段或路段更危險。
- 警方研判肇因呈現紀錄分類，不能單憑圖表證明因果關係。
- 當事者年齡分布不能直接推論某年齡層較容易發生事故，亦不是年齡別傷亡人數。
- 熱力圖原始件數受資料期間與各星期出現天數影響；若比較每日平均，需明示分母。
- 箱型圖離群點是統計標記，不代表資料必然錯誤。
- 觀察結果可能受資料缺漏、分類差異、地點正規化與事故識別方式影響。
